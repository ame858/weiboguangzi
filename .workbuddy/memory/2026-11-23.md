# 2026-11-23

## 新增 FastAPI Web 工作台（替代 Streamlit app.py）
- 新增 `server.py`、`requirements-web.txt`、`web/index.html`、`web/app.js`；`videosar_ui/`、`tests/`、`videosar/` 未改动。
- 启动：`./.venv/Scripts/python.exe server.py` → http://127.0.0.1:8000（依赖已装进 .venv：fastapi 0.165 / starlette 1.10 / pydantic 2.14 / uvicorn 0.54）。
- 设计要点：
  - `_MtimeLRU` 缓存 sequence/predictions/tracks，按文件 mtime 作 key。
  - `POST /api/browser/frames` 批量出帧，前端帧缓存池预热 + 播放时提前 4 帧预取。
  - 子进程任务跑在线程里，日志走 SSE（`/api/jobs/{id}/stream`）。
  - 媒体 URL 一律 `urllib.parse.quote`，修掉 Windows 反斜杠/中文/空格路径打不开的问题（upload 首帧 URL、导出下载、overlay）。
- 性能关键发现：`scan.find_results` 每次调用要遍历 runs（7 788 目录 / 56 k 文件）≈4.3 s，页面加载会调两次。
  - 改用自建 `_runs_index`（一次遍历同时产出 sequences + 三类结果目录 + source.json 里的 sequence 尾巴），
    内存 TTL 60 s + 磁盘缓存 `%TEMP%/videosar-workbench/runs-index-<hash>.json`（10 min），冷启动 sequences 172 ms。
  - `_same_path` 必须用 `abspath+normcase` 而非 `Path.resolve()`（resolve 每个候选一次 stat，2116 个 ≈0.8 s/次）。
- 数据坑：`runs/closeout-demo-{detect,track,eval}/source.json` 记的是 `runs\echo-stress\...`，
  实际序列在 `runs/echo-stress-repro/...`，绝对路径比对失败 → 加「目录尾 2 段匹配 + 形状/帧数校验」自动配对，
  现在优先序列默认能直接秒播完整四宫格 + 指标（precision/recall 1.000，IoU 0.864）。
- 实测：单帧渲染 13–45 ms（8 fps 预算 125 ms），播放 1.2 s 走 10 帧；demo 全链路 SSE 2.2 s 完成。

  `runs/snl-video-prefix-v2/overlay.mp4` 返回 2 条，测试断言 1 条），与本次改动无关，未动测试。
